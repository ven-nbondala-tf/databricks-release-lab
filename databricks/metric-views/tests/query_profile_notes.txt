Query: SELECT nation, MEASURE(total_revenue) AS rev FROM release_lab.metric_demo.orders_metrics GROUP BY nation ORDER BY rev DESC
Run on a serverless SQL warehouse, DBSQL 2026.46. 25 rows returned.

Summary panel
- Total wall-clock duration: 1 s 349 ms. Result fetching by client: 39 ms.
- Rows read: 8,250,025. Bytes read: 53.66 MB. Files read: 5. Bytes read from cache: 100%.
- Rows read equals 7,500,000 (orders) + 750,000 (customer) + 25 (nation).
- Tasks total time 1.58 s, 91% in Photon. Rows written 0, spill 0.

Graph (28 operators), main path from the bottom:
- #9 Scan Table (7.50 M rows) -> #8 Shuffle -> #7 Left Outer Join (7.50 M rows out) -> #6 Grouping Aggregate (225 rows) -> #5 Shuffle -> #4 Grouping Aggregate (25 rows) -> #3 Sort -> #2 Columnar To Row -> #1 Result Query Stage.
- The right input of #7 is the customer side: #19 Scan Table (750 K rows) is joined by #18 Left Outer Join with a nation side, then #17 Sort, #16 Window, #15 Filter, #14 Shuffle, #13 Sort, #12 Window, #11 Filter, #10 Shuffle (750 K rows each) feed #7.
- The nation side: #28 Scan Table (25 rows), #27 Sort, #26 Window, #25 Filter, #24 Shuffle, #23 Sort, #22 Window, #21 Filter, #20 Shuffle (25 rows each) feed #18.
- Three Scan Table operators in total (orders, customer, nation), two Left Outer Join operators, and a Sort, Window and Filter chain on each joined side.
- The profile does not name the tables on the graph nodes; the table names come from EXPLAIN (see explain_dimension.txt).
