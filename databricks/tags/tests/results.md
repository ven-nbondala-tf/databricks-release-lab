### ABAC test details (sql/06 to 08)
- Governed tag sensitivity set on the CATALOG (value low). The table sales_orders has no sensitivity tag of its own.
- Policy small_orders_only on schema tags_demo: row filter, TO `account users`, WHEN has_tag_value('sensitivity', 'low'), MATCH COLUMNS has_tag('amount_col'), where amount_col is a second governed tag set on the amount column.
- Before the policy: 5 rows. With the catalog tag and the policy: 3 rows (orders under 200), within the first query after creation. After UNSET TAG ON CATALOG sensitivity: 5 rows again straight away. So a tag set on the catalog affected the table beneath it, and removing it switched the policy off.
- The first CREATE POLICY failed right after CREATE GOVERNED TAG amount_col with INVALID_PARAMETER_VALUE.UC_INVALID_POLICY_CONDITION ("Invalid condition in policy 'small_orders_only'. Compilation er..."; message cut off in my log). The same statement succeeded a minute later. Likely the new governed tag had not propagated yet.
- State now: the policy small_orders_only still exists on tags_demo (kept for the screenshot), the catalog tag sensitivity is unset.
